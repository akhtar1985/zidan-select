Every form control, one small library.

ZidanForm upgrades native inputs in place — select, checkbox, switch, radio, file upload and text fields — while keeping real form values, FormData, form.reset() and constraint validation intact. Structure ships separately from the theme, so you can restyle everything with a handful of CSS variables.

Input icons — auto, built-in, custom

Auto picks the icon for the type; data-zidan-icon takes a built-in name, your own registered name, or raw SVG markup. Date/time fields use the icon as their picker button.

<!-- data attributes -->
<input data-zidan="input" data-zidan-auto-icon="true">
<input data-zidan="input" data-zidan-icon="link"
       data-zidan-icon-position="right" data-zidan-icon-clickable="true">

// JS options — no data attributes needed
zidanField('#icon-js', {
  icon: 'palette', iconPosition: 'right', iconClickable: true
});

// custom artwork: register once, before fields initialise
ZidanForm.registerIcon('sparkle',
  '<path d="M12 3l1.9 5.3L19 10l-5.1 1.7L12 17Z"/>');

Built-in names: text mail phone user lock search calendar clock link hash palette sliders file upload eye eye-off check x plus minus chevron-* alert info globe map-pin image refresh trash. icon also accepts raw <path> or <svg> markup. The last field above is initialised entirely from JavaScript.

    Why ZidanForm

    One library for the whole form

    Select libraries usually stop at the select box. ZidanForm styles every native control with the same API and the same two stylesheets — and never hides the real input.

    ◎

    One API, every control

    Select, combobox, tags, checkbox, switch, radio, file upload, text, phone, stepper, range and date/time inputs share one lifecycle and one theme.

    ✓

    Native underneath

    The real control stays in the DOM at 1×1 px, so FormData, reset(), required and :invalid keep working.

    ◐

    Theme without forking

    Structure lives in plugin-core.css, colour and skins in plugin-theme.css — override tokens, not layout.

    Questions

    Frequently asked

    The short answers. The detailed ones live in the docs.

    Does it require jQuery?

    No. ZidanForm is vanilla JavaScript with no runtime dependencies. It works alongside jQuery, but never needs it.

    Will FormData, reset and validation still work?

    Yes. The native control stays in the DOM at 1×1 px and is only visually covered, so FormData, form.reset(), required, :invalid and input.files behave exactly as before.

    Can I use it with React, Vue or Angular?

    Yes — initialise in a mount/effect and call destroy() on cleanup. The framework guide covers React, Next.js SSR, Vue and Angular patterns.

    Does it conflict with jQuery Validation, JustValidate or Parsley?

    No. These libraries ignore hidden fields, so ZidanForm keeps the native control reachable and syncs aria-invalid. There is a runnable test bench for all four validators.

    How do I customise the look?

    Load plugin-core.css then plugin-theme.css, and override CSS variables or add a theme. Register custom names with ZidanForm.themes.push('brand') before initialising. See theming.

    Can I enhance just one select?

    Yes. Everything is opt-in: add a data-zidan-select attribute, initialise only that element, or call zidanField() / zidanSelect() directly. destroy() restores the original markup.

    Is there a build step or bundler requirement?

    No. It ships as a classic script, an ESM wrapper and plain CSS. Use a CDN, npm, or copy the files; no compiler or bundler is required.

    Which browsers are supported?

    Current Chromium (105+), Firefox (121+) and Safari 15.4+ / iOS 15.4+. Firefox exposes thin native scrollbars only. See the browser matrix in the theme showcase.
