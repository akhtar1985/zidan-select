Options & data attributes

Everything is opt-in. A control is enhanced only when it carries a data-zidan* attribute, carries a marker class, sits inside a form scope, is matched by a configured target, or is passed to initZidanSelects() / initZidanForms() / zidanSelect() / zidanField(). zidanField() itself accepts any supported <input>/<textarea>, with or without a data-zidan* attribute, which is how JS-only options are applied.

Prefer to click through the options? The field playground exposes the main options for one control at a time and copies both supported HTML attributes and vanilla JavaScript. The API lab exercises the complete option, callback, method and event inventory.

Direct init by ID or class

The first argument of zidanSelect() accepts a CSS selector, an element, or a NodeList. Plain selects are not auto-initialised, so you can enhance exactly the field you want. For complete copy-paste pages (static HTML, WordPress, page builders) see the static HTML & WordPress cookbook.

<select id="mymov">…</select>
<select class="mymovclass">…</select>
<select class="mymovclass">…</select>
const picker = zidanSelect('#mymov', {
  mode: 'combobox',
  label: 'Movie',
  placeholder: 'Search a movie…',
  searchable: true,
  clearable: true
});

const pickers = zidanSelect('.mymovclass', { mode: 'select', layout: 'soft-pill' });
// one match → instance, several → array

initZidanSelects(scope, options) still bulk-enhances every [data-zidan-select] and .zidan-select inside a scope; use it when the markup can carry attributes. zidanSelect() is the targeted form for IDs, classes and elements you already have a reference to.

Both bulk helpers skip elements that are already enhanced. Pass { force: true } (initZidanForms(scope, { force: true }), ZidanForm.init(scope, { force: true })) to re-initialise them, for example after swapping markup. The same entry points are on the global object as ZidanForm.init(), ZidanForm.get(), ZidanForm.refresh(), ZidanForm.observe(), ZidanForm.destroy(scope?), ZidanForm.destroyAll() and ZidanForm.version.

Read values and option details

picker.getValue();                 // selected value; array for multiple/tags
picker.setValue('dune');
picker.getTags();                  // tags mode

const native = picker.el;          // the original <select>
native.selectedOptions;            // selected <option> elements
Array.from(native.options).map(option => ({
  value: option.value,
  label: option.text,
  disabled: option.disabled,
  group: option.parentElement.tagName === 'OPTGROUP' ? option.parentElement.label : null
}));

picker.setOptions([                // rebuilds listbox and native <option>s
  { value: 'inception', label: 'Inception' },
  { value: 'dune', label: 'Dune', group: 'Villeneuve' },
  { value: 'arrival', label: 'Arrival', disabled: true }
]);

Listen to the library callback in the options (onChange: ({ instance, value }) => …) or to the native change event; the native <select> always holds the current value.

No-JS init (IDs, classes, selectors, JSON)

data-zidan-options JSON

Plain options as JSON on the element itself, for selects and every field type:

<select class="zidan-select" multiple
        data-zidan-options='{"mode":"tags","maxTags":3,"placeholder":"Add a tag…"}'>…</select>

<input type="file" class="zidan-field"
       data-zidan-options='{"variant":"gallery","maxFiles":4,"title":"Add images"}'>

Values must be literal JSON; callbacks, upload functions and raw SVG icon markup still need a small JS block. Invalid JSON is ignored with one console warning.

window.ZIDAN_FORM_CONFIG = {
  targets: ['#country', 'select.product-variants',
            { selector: '#brands', options: { mode: 'tags', maxTags: 3 } }],
  fieldTargets: [
    { selector: '#avatar', options: { variant: 'avatar' } },
    { selector: 'input[name="email"]', options: { icon: 'mail' } }
  ],
  formTargets: ['#checkout']
};

Precedence for any single option: per-target options → data-zidan-options JSON → data-zidan-* attribute → default. Config is read during the DOMContentLoaded pass, so set it before the library script (or call initZidanSelects() / initZidanForms() yourself with the same values). Explicit targets run first so their options win over the generic scan.

  rangeVariant: 'gradient',

zidanField('#delivery', {
  rangeBubbleMode: 'active',      // 'always' | 'active' | 'never'
  rangeBubblePosition: 'bottom',  // 'top' | 'bottom'
  rangeFill: false,               // neutral track, no progress colour
  rangeTicks: '0,10,20,30',       // count, array, JSON or comma list
  rangeTickLabels: true,
  rangeMinLabel: 'Low',
  rangeMaxLabel: 'High'
});

The range keeps input.value native; only the visual chrome and bubble are added. Instance properties range, rangeBubble, rangeTicksEl and rangeScale are exposed if you need to re-render custom ticks.

Labeled ticks and the scale do not stack: when rangeTickLabels is on and the tick values include both min and max, the scale row (.zs-range-scale) gets zs-range-scale--hidden and the tick labels are the single endpoint readout. rangeLabels entries win over rangeFormat for that value. Endpoint labels carry zs-range-tick--start / --end and the bubble gets zs-range-bubble--start / --end, so both stay inside the track at 0 and max, including in RTL. Without a scale row (.zs-range--labels-no-scale) the label height is reserved so labels cannot overlap the next element.

Bubble behaviour is controlled by rangeBubbleMode (always / active / never) and rangeBubblePosition (top / bottom), the coloured progress by rangeFill, and the scale ends by rangeMinLabel / rangeMaxLabel. rangeFill: false keeps the neutral track but not the gradient skin, and rangeFormat also feeds aria-valuetext so assistive tech reads the formatted value.

Custom uploader contract:

zidanField('#files', {
  upload(file, context) {
    // file: the File being uploaded
    // context: { file, field, formData, signal, onProgress, complete, fail }
    const xhr = new XMLHttpRequest();
    // ...or return a promise / call context.complete(result) / context.fail(error)
    context.onProgress(40);              // 0–99 while working
    fetch('/upload', { method: 'POST', body: context.formData, signal: context.signal })
      .then(res => res.ok ? res.json() : Promise.reject(res.status))
      .then(data => context.complete(data))
      .catch(err => context.fail(err));
  }
});
  • A returned thenable resolves the upload; a non-undefined return value becomes the result.
  • Returning nothing means you will call context.complete() / context.fail().
  • context.signal aborts when the user cancels or the field is destroyed.
  • input.files is always authoritative; DataTransfer rebuilds it on remove/clear.

Methods: getFiles(), getUploadState() and getFileState(fileOrNameOrIndex) ({ file, name, size, status, progress, error, result, attempts }), addFiles(files), replaceFiles(files), removeFile(fileOrNameOrIndex), removeFiles([fileOrNameOrIndex, …]), clear(), isUploading(), whenUploaded() (resolves all states after the queue drains), uploadAll(), uploadFile(file), cancelUpload(file), cancelAll(), retryUpload(file), retryAll(), setVariant(name), setUploader(fnOrUrl), setUploadUrl(url) and setUploadOptions({ … }).

uploadAll() returns the field for synchronous validation and a Promise<boolean> when an async rule runs. whenUploaded() is the reliable way to wait for AJAX uploads, retries and queued files.

Events: zidan:upload-queued { file, name, size, position }, zidan:upload-start { file, name, size }, zidan:upload-progress { file, name, progress }, zidan:upload-retry { file, name, attempt, nextAttempt, delay, error, message }, zidan:upload-success { file, name, result }, zidan:upload-error { file, name, error, message }, zidan:upload-cancel { file, name }, plus the shared zidan:change, zidan:remove ({ file, index }) and zidan:clear.

AJAX transport, queue and retries

When uploadUrl is set, each file is sent as FormData with the configured field name. uploadParams are appended to the URL as a query string (arrays repeat the key), while uploadData and the file itself become multipart fields. Array values in uploadData append repeated form keys. uploadHeaders may be an object or a (file, field) => object function; array header values are joined with ", ".

The response is parsed as JSON when possible. uploadResponsePath selects a nested value with dot notation (for example data.url); uploadErrorPath reads a message from a failed body. HTTP statuses 408, 429, 5xx, network errors and timeouts are retryable. Automatic retries use uploadRetries and uploadRetryDelay; a manual retry is available through the per-file button, retryUpload(file) or retryAll(). Set uploadConcurrency to cap parallel requests; the remaining files stay queued and start automatically.

const field = zidanField('#files', {
  uploadUrl: 'https://httpbin.org/post',
  uploadMethod: 'POST',
  uploadParams: { demo: 'zidan-form' },
  uploadData: { source: 'demo' },
  uploadHeaders: { 'X-Demo': 'file-upload' },
  uploadTimeout: 30000,
  uploadRetries: 1,
  uploadConcurrency: 2,
  uploadResponsePath: 'url',
  autoUpload: false
});

field.uploadAll();
const states = await field.whenUploaded();

A custom uploadHandler still runs instead of XHR and keeps the same queue, retry, cancel and whenUploaded() behaviour.

Browser-side image downscale

Set downscale: true to resize images before any uploader runs. The default caps the longest edge at 1920 px and re-encodes as JPEG (PNG stays PNG) at quality 0.85, skipping files that are already small enough.

  uploadUrl: '/api/avatar'

// standalone helper

The compressed file keeps the original file's upload state row, name and FormData field. If the browser has no canvas support, or the resized image would be larger than the original, the original file is uploaded unchanged.

Remote results are not filtered again on the client, so a server that already applied the query is never double-filtered. Use renderOption for custom rows; keep values stable across pages so the merge can de-duplicate them.

const users = zidanSelect('#owner', {
  mode: 'combobox',
  fetchPageSize: 20,
  fetchOptions: async (query, signal, { page, pageSize }) => {
    const res = await fetch('/api/users?q=' + encodeURIComponent(query)
      + '&page=' + page + '&size=' + pageSize, { signal });
    const data = await res.json();
    return {
      items: data.rows.map(u => ({ value: u.id, label: u.name })),
      hasMore: data.page + 1 < data.pages
    };
  },
  onLoadMore: ({ page }) => console.log('loaded page', page)
});

users.loadMore();                 // manual next page
users.hasMoreResults();           // boolean
users.getAsyncState();            // { query, page, hasMore, loading, fetchingMore, error }
users.refreshOptions();           // clears the cache and refetches page 0
users.clearCache();               // drop cached pages only

fetchOptions may also reject: an initial failure shows an error state and getAsyncState().error keeps the message; call refreshOptions() to retry. If an appended page fails, the rows already loaded stay visible and the footer shows the error; clicking it retries. Appended fetches emit zidan:load-more with { page, query }; failures emit the usual zidan:error.

The cache size is global: ZidanSelect.cacheLimit = 50 pages (least-recently-used eviction).

AJAX from markup only

One URL is enough to turn a combobox into a remote search. The plugin sends the query, page and page size, reads the rows out of the JSON, and keeps every other behaviour (debounce, abort, cache, load-more, errors) identical to a hand-written fetchOptions.

<select id="product" name="product"
        data-zidan-select="combobox"
        data-zidan-fetch-url="/api/products/search"
        data-zidan-fetch-items-path="data.items"
        data-zidan-fetch-total-path="data.total"
        data-zidan-fetch-skip-param="skip"
        data-zidan-fetch-params='{"tenant":"north"}'
        data-zidan-fetch-page-size="20">
</select>

That markup calls GET /api/products/search?q=…&limit=20&skip=0&tenant=north, then skip=20 for the next page, and stops when skip + limit >= data.total. Rows map automatically: value / label, or id / slug / code for the value and name / title / full_name for the label. A live page with both modes, against a real API and a static JSON file, ships as ajax.html.

For an endpoint that expects a JSON search body, keep the same declarative setup and add a method, params and body — no fetchOptions function required:

<select id="order" name="order"
        data-zidan-select="combobox"
        data-zidan-fetch-url="/api/orders/search"
        data-zidan-fetch-method="POST"
        data-zidan-fetch-params='{"scope":"open"}'
        data-zidan-fetch-body='{"status":["open","paid"]}'
        data-zidan-fetch-items-path="rows"
        data-zidan-fetch-total-path="total">
</select>

POST /api/orders/search?q=…&scope=open is sent with Content-Type: application/json and the JSON body. Use the api.html request lab to inspect the exact URL, headers and body the plugin builds before pointing it at your own endpoint.

Large lists, search quality and locales

Virtual window

Local lists with hundreds of rows render only the visible slice. Windowing is on by default (virtual: 'auto', from 150 rows) and skipped for grouped lists, custom renderOption renderers and paged results, where row heights or extras change per row.

zidanSelect('#city', { virtual: 'auto', virtualThreshold: 150, itemHeight: 38 });
  • virtual: 'auto' (the default) windows once the filtered list reaches virtualThreshold; true always windows, false disables it, a number sets the threshold directly.
  • itemHeight fixes the row height used for spacer math. Leave 0 to measure the first row.
  • Rows keep aria-setsize / aria-posinset; keyboard Home, End, ↑, ↓ and type-ahead scroll the window and keep aria-activedescendant on the active row.
  • The dropdown must have a measured height (it opens with maxDropdownHeight); a hidden or zero-height list falls back to full rendering.

Accents and highlights

zidanSelect('#city', { accentInsensitive: true, highlightMatches: true });

accentInsensitive (default true) folds diacritics in both the query and the option label/value, so cafe finds Café and zurich finds Zürich. Set it to false for exact matching. highlightMatches wraps the matched slice in <mark class="zs-match">; --zs-match-bg themes it.

Type-ahead

Selects that are not searchable are read-only, but printable keys still jump like a native <select>: the buffer expires after typeAheadTimeout (default 600 ms), repeating the same letter cycles through options starting with it, and typeAhead: false disables the behaviour.

Locales

zidanSelect('#city', { locale: 'fr' });
ZidanSelect.locales.nl = { emptyText: 'Geen opties', noResultsText: 'Geen resultaten' };

Bundled packs: en, es, fr, de, ar. Pass a locale name or a partial pack; a pack only fills values you have not overridden (including requiredText and the default placeholder). <html lang="…"> selects the pack automatically when locale is unset, and the root gets a matching lang attribute. ZidanForm.locales is the same object, so registrations are global and take effect for instances created afterwards.

Theme auto

zidanSelect('#city', { theme: 'auto' });   // or data-zidan-theme="auto"

auto resolves to dark when prefers-color-scheme: dark matches and default otherwise. A single shared matchMedia listener updates every auto root when the OS setting changes; setTheme('auto') re-arms it and destroying the instance unregisters it. ZidanForm.themes includes auto.

Option groups and getTags

Options with group render <div role="group" aria-labelledby="…"> wrappers with a .zs-group-label header, so the listbox exposes the grouping instead of flattening it. In tags mode getTags() returns the tag values (string[]), matching its declaration.

Static select helpers: ZidanSelect.get(target) returns the instance for a native select, ZidanSelect.destroy(scope?) restores only the selects inside a document/element/selector and returns the count, and ZidanSelect.destroyAll() covers the whole document. Field teardown for a subtree is ZidanForm.destroy(scope?); see Form-level helpers.

Multiple helpers: getSelectedItems(), selectAll(config?), deselectAll(config?), toggleAll(config?) and areAllSelected(). They cover every non-disabled option (not only the rows matching the current search) and accept { silent: true } like setValue. Tag helpers: moveTag(from, to) and editTag(tagOrIndex, label) return a boolean and keep the native options in sync.

setValue(value, config?) and clear(config?) take { silent: true }, which updates the value, the native <select> and the rendered control without emitting zidan:change or calling onChange.

Form-level helpers

ZidanForm.serialize(form, options?) returns an object built from FormData: repeated names become arrays and file inputs are skipped unless { files: true }.

ZidanForm.validate(form, options?) resolves true/false after every enhanced field's validate() and the native form constraints run. It focuses the first invalid control (set { focus: false } to skip) and dispatches zidan:validate with { valid, form, fields }.

const form = document.querySelector('#signup');
const data = ZidanForm.serialize(form);
if (await ZidanForm.validate(form)) {
  await fetch('/signup', { method: 'POST', body: JSON.stringify(data) });
}

ZidanForm.destroy(scope?) restores only the fields and selects inside a document, element or selector and returns the number of instances removed. It is the recommended cleanup for component frameworks because a route or modal only owns its own subtree. With no argument it covers the document, like destroyAll().

ZidanForm.mask(value, pattern), ZidanForm.unmask(value) and ZidanForm.downscaleImage(file, options) are also available as standalone helpers.

Events

Removing an already-selected option from a multi-select (the option row or its chip) emits zidan:deselect and then change; a tag removed from a tag field emits zidan:tag-remove and change. Programmatic setValue(), clear() and deselectAll() do not emit deselect: it reports user intent only.
