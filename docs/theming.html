Theming

plugin-core.css contains structure only: layout, positioning, the 1×1 px native-input mechanism and visibility rules. Every colour, border, shadow and skin is in plugin-theme.css, driven by --zs-* custom properties.

Load order:

<link rel="stylesheet" href="plugin-core.css">
<link rel="stylesheet" href="plugin-theme.css">
<link rel="stylesheet" href="my-theme.css">   <!-- optional overrides -->

Themes and frameworks resolve independently: you can combine dark + bootstrap.

Public styling contract

  • Stable: the --zs-* custom properties in the tables below, and the data-zs-theme / data-zs-framework attributes.
  • Stable layout utilities: zs-form-grid, zs-full and the zs-match mark hook.
  • Implementation hooks: every other zs-* class and internal data-zs-* marker. They can change between minors; do not use them as a compatibility contract. Style through tokens or your own wrapper class instead.

Variant hooks

Variants are selected per control and can be restyled with attribute selectors — no JS:

/* checkbox pill */
.zs-field[data-zs-variant="button"] .zs-check { --zs-pill-bg: #ecfdf3; }
/* radio tiles */
.zs-radio-group[data-zs-variant="tile"] .zs-radio { border-radius: 14px; }
/* switch skins */
.zs-field[data-zs-switch-style="ios"] .zs-switch-track::after { box-shadow: 0 1px 3px rgba(0,0,0,.3); }
/* file variants */
.zs-field[data-zs-file-variant="avatar"] { --zs-avatar-size: 128px; }
.zs-field[data-zs-file-variant="gallery"] .zs-file-list { grid-template-columns: repeat(auto-fill, minmax(96px, 1fr)); }
/* range skins */
.zs-range[data-zs-range="gradient"] { --zs-range-gradient: linear-gradient(90deg, #22c55e, #eab308); }

data-zs-file-variant is set on the field root; the drop target also carries zs-file-drop--<variant>. data-zs-range is set on .zs-range, and validation-driven icons/progress are keyed off [data-zs-validation] and data-zs-upload-state.

<form class="my-brand">…</form>

No JS change is needed when the tokens apply to a wrapper class. For a named preset that also works with data-zs-theme="brand" and setTheme('brand'), register the name first:

ZidanForm.themes.push('brand');   // register before fields initialise
<form data-zs-theme="brand">…</form>
[data-zs-theme="brand"] { /* tokens */ }

ZidanForm.themes is the live list the plugin validates against, so a pushed name survives initialisation and is written to the field root as data-zs-theme. Names that were never registered fall back to default; pushing after fields exist only affects setTheme() calls made afterwards.

Automatic dark mode

theme: 'auto' (or data-zs-theme="auto") resolves to dark when the OS prefers dark and to default otherwise:

zidanSelect('#city', { theme: 'auto' });

One shared matchMedia('(prefers-color-scheme: dark)') listener updates every auto root live; setTheme('auto') re-arms it and destroy() removes the tracking. auto is resolved in JS, so there is no [data-zs-theme="auto"] CSS block — the root carries the resolved dark/default name. To drive it yourself instead, set the attribute before init:

<script>
  if (matchMedia('(prefers-color-scheme: dark)').matches) {
    document.documentElement.setAttribute('data-zs-theme', 'dark');
  }
</script>

setTheme() on an instance does the same for one field.

grid is not a field layout value — the grid lives on the wrapper:

<div class="zs-form-grid">
  <input data-zidan="input" data-zidan-label="First name">
  <input data-zidan="input" data-zidan-label="Last name">
  <textarea data-zidan="textarea" data-zidan-label="Notes" class="zs-full"></textarea>
</div>

--zs-grid-min / --zs-grid-gap control the auto-fit columns.

Framework adapters

data-zs-framework (or the framework option; themeFramework is a deprecated alias) accepts none, bootstrap, tailwind, bulma and foundation. The legacy value vanilla is accepted and behaves exactly like none. Adapters only remap tokens plus a few structural compat rules (Bootstrap input-group, for example). Nothing depends on the framework's JavaScript.

<html data-zs-framework="bootstrap">   <!-- whole page -->
<form data-zs-framework="tailwind">    <!-- one form -->
